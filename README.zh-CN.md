# 循证医学科研写作

**Evidence-First Medical Writing**

<img src="assets/logo.png" alt="循证医学科研写作图标" width="144">

[English README](README.md)

这是一个用于起草、修改和审阅医学科研论文的双语 Codex skill。

本工具参照国际医学出版规范设计，帮助作者更清楚、准确地报告研究；作者须遵守目标期刊的 AI 使用与披露政策，并对提交内容负责。

本 skill 由广西医科大学第一附属医院眼科神经眼科团队的 Yi Du 教授维护。机构和团队仅用于说明个人所属，不代表医院或团队官方发布、授权或背书。本项目独立于出版社、期刊、平台及其他第三方。联系邮箱：[duyinapoleon@gmail.com](mailto:duyinapoleon@gmail.com)

方法来源说明：本工作流基于多来源医学科研写作与编辑实践，提炼可迁移的方法原则、工作流与检查表，不公开私人写作资料的具体来源。复用的软件组件单独注明来源，并保留其许可证。

仓库地址：<https://github.com/duyi-neurooph/evidence-first-medical-writing>

## 主要能力

- **临床表格与纳排流程图（1.0.7）**：表格中清楚区分变量与下属类别，后续修改 Word 稿也保留作者已确认的排版。流程图只放解释分母变化所需的内容，无关临床细节留在正文或表格。
- **统计分析材料交付（1.0.6）**：若作者另行委托，且可用工具确实计算了论文数值，作者应得到能重跑的文件。参见[哪些计算要留、什么时候共享](skills/evidence-first-medical-writing/references/statistical-policy-router.md#handoff-for-an-authorized-analysis-run)。纯排版不触发，本 skill 不内置统计引擎。
- **投稿细节（1.0.5）**：核对原分析者实际使用的统计软件及关键包版本，不新增统计分析功能，也不推断是否用过 AI。按目标期刊统一参考文献中的文章题名大小写，将格式问题与文献错引分开。投稿信优先称呼负责该稿的编辑；未指定时核实主编或共同主编。
- **投稿排版和统计表（1.0.3）**：期刊未指定模板时，标题优先用黑字、字号和留白区分，不加装饰横线（含 Word 标题样式继承的底边框）、色带或底纹；保留有信息作用的表线、图例和作者脚注。单看统计表即可知道每个报告的 P 值对应哪种实际检验：混用方法时用期刊允许的上标符号或字母逐值对应表注；确实同一方法时，一条表注明确覆盖全表即可。多分类变量的总体检验标在变量行，不当成各类别的两两比较；方法标记不与显著性星号混用。以作者确认的分析为准，不猜方法，也不为标注新增检验。
- **P 值精度（1.0.3）**：以目标期刊要求为先；期刊无不同要求时，按**未舍入值**判断：小于 0.001 写 `P < 0.001`；0.001 至 0.999（含两端）用等号并保留三位小数（含末尾零）；大于 0.999 但小于 1 写 `P > 0.999`；仅确认精确等于 1 时可写 `P = 1.000`。软件舍入显示的 `1.000` 不代表精确等于 1，已有 `P < 0.05` 也不能反推具体数值；必要时向作者索取更高精度的输出。
- **写作示例（1.0.1）**：遇到具体写作问题时，按需查阅随包附带的[正反例卡片](skills/evidence-first-medical-writing/references/writing-example-cards.md)，离线也能用。正例说明哪些准确的表述值得保留；反例说明读者可能误解什么，以及怎样修正。示例均为虚构，不是研究证据，不能用来补写稿件事实。
- **标题与摘要（1.0.1）**：只看标题，读者会以为这是一项什么研究？单读摘要，又能得出什么结论？先分别记录两次阅读的判断，再用实际研究设计和已有结果核对。只有可能引起误解时才建议最小修改；不改事实、数字或结论，原文准确就保留。
- **患者流程图（1.0.4）**：只说“按我给你的数据画 flowchart”即可，不用提期刊名。先核对单位和分母：[保留的分组向下，只有真正排除才向右](skills/evidence-first-medical-writing/references/participant-flow.md)。可编辑 SVG 使用人数、对齐的框和简短图题，来源核对记录另存。可用这组[英文虚拟试验数据](skills/evidence-first-medical-writing/assets/flow-community-bp.json)试画。
  观察性研究另有两套独立的英文虚拟数据：[队列研究纳排](skills/evidence-first-medical-writing/assets/flow-observational-cohort.json)和[病例对照研究抽样](skills/evidence-first-medical-writing/assets/flow-case-control.json)。

- **0.8.0 新增**：“投稿前检查”自动执行[书目身份与原文支持程度核查](skills/evidence-first-medical-writing/references/reference-verification.md)。先逐条核对书目，再回到原文核对关键主张；默认不改原稿及文献库。独立 skill 已含所需 Python 脚本及[上游 MIT 许可](skills/evidence-first-medical-writing/third-party/aperivue-verify-refs.md)。
- 建立研究任务卡、PICO-T、核心命题和 IMRaD 大纲；
- 检查研究问题、设计、终点、分析、结果与结论是否一致；
- 在语言润色前发现研究诚信和报告风险；
- 应用特定报告指南前，与作者确认真实研究类型，针对缺失的关键事实提问，不直接相信“随机”“前瞻性”等标签；
- 在实质性写作或审稿前，从 EQUATOR 及官方来源获取适用报告指南，记录版本并逐项提出改进建议；
- 按任务参考 JAMA 研究类型定义及 NEJM 统计报告指导，不用它们替代实际目标期刊的稿约；
- 提供可离线使用的统计审查参考；使用时检查正式版更新，可在授权且安全的独立安装中自动更新；
- 投稿前简短提醒作者按目标期刊现行政策披露 AI 使用，提示当前任务与政策的冲突；不记录 AI 使用历史，不自动起草披露声明；
- 修改题目、摘要、正文各章节、图表、投稿信和审稿回复；
- 运行“独立多审稿人—编辑裁决—迭代修改”的模拟同行评审，并维护 Decision Ledger 和 Non-Regression Check；
- 对最终投稿文件进行十项交叉核查，覆盖数据、引用、编号、流程、注册、术语、统计表达、入排标准、作者贡献和修回回复；
- 可选核对获准共享、去标识化的数据与图表及统计方法，提供异常线索与核查建议，不声称能够判定造假；
- 支持随机研究、观察性研究、诊断、预测、系统综述/Meta、病例类和短文等常见类型；
- 按 `P0 可信度阻断项`、`P1 研究逻辑`、`P2 结构与自明性`、`P3 语言与格式` 分级输出问题。

## 安全边界

本 skill 不得：

- 编造数据、方法、注册、伦理批准、引文或审稿决定；
- 为追求显著性而改变终点、阈值、分析集或结论；
- 把相关性升级为因果，或把无统计学显著性写成等效；
- 隐瞒阴性主要结果、局限、偏离、错误或不确定性；
- 冒充真实个人或复现可识别的个人文风；
- 在没有可核验许可时宣称授权、背书、隶属或官方身份；
- 暴露患者信息、保密手稿、私人通信或身份映射。

它用于辅助写作和研究推理，不能替代临床判断、统计签字、伦理审查、法律意见或目标期刊的最新要求。

### 使用时检查更新与可选自动更新

每个写作新任务开始时，只在对话中用你惯用的语言提示一次**当前任务实际加载的版本**。联网核实了官方稳定版，才根据结果明确说“已是最新版”或“有可用更新：vX”；未能核实时直接说明。从网上下载或更新到磁盘的版本，不等于本次对话已加载的版本。提示也会简短提醒：数据如何解释由你把关；投稿前请遵守目标期刊的 AI 使用与披露政策。版本和提醒均不写入投稿文件。

确认首次安装或升级成功后，可用你的惯用语言给出一两句寄语。如果平台静默安装或无法确认是否显示，在实际用该版本写作时可随首次版本提示补发；已显示就不重复。只查版本不发，也不写入稿件、图及其他交付文件。详见[随包说明](skills/evidence-first-medical-writing/references/updates.md)。

从 0.7.1 起，在每个新任务开始时，若平台允许联网及相应工具，会检查官方最新正式版。这不是后台常驻服务；**0.7.1 之前的用户需要先手动安装 0.7.1 或更新版本**，旧副本不会凭空获得更新能力。

默认只检查和提示。经你明确选择自动更新后，内置的 Python 3 标准库程序可更新未被修改、可写入的独立 skill 文件夹：核对官方附件身份、SHA-256 和文件清单，默认保留旧版 ZIP（可单独为本安装关闭），不覆盖自定义改动。源码仓库、插件包及平台管理的缓存使用各自更新方式。缺少工具、权限不足、版本锁定、离线或验证失败时，只提示或提供手动下载链接，不强行安装。更新后请在新任务中重新调用；同一轮审稿不会中途换版本。

开启、关闭、仅检查及锁定版本的操作见[更新说明](skills/evidence-first-medical-writing/references/updates.md)。也可以直接对 AI 说：

### 过度防御性科学写作检查

实质性起草、语言改写、手稿修订、整稿审查、模拟同行评审及最终核查时，区分“必要的科学限定”和“反复免责声明”。检查跨章节、正文与表格、补充表及图注的语义重复，不统计否定词数量，也不强行改写准确自然的句子。它补充现有“去 AI 化”检查，不取代该检查。

逐项给出位置、原文、问题、删除后的科学风险、处理决定和建议改写。处理分为“保留、合并、换一种直接表达、删除、作者决定”。阴性主要结果、因果边界、分析层级、安全伦理信息及摘要或表格独立阅读时必需的限定必须保留；不能为了填满表格而编造新局限。单纯拼写、格式或字面翻译不触发全文审查。

```text
使用 $evidence-first-medical-writing 检查并修改这篇稿件的过度防御性写作。
找出跨章节和表格中的重复限定，先说明删除的科学风险，再提出修改。
保留我的科学判断、必要证据边界和阴性主要结果；记录保留与删除的限定，
防止后续审稿重新加入。不要编造缺失的事实或局限。
```

此功能从 0.6.0 版本开始提供。

### 使用时自动获取适用报告指南

实质性规划、写作、改写或审稿时，skill 会先与你讨论研究类型：说明初步判断及依据，必要时只追问关键事实，例如治疗由谁决定、是否真正随机分配、如何选入受试者，以及研究计划和结局收集的时间关系。不能仅凭标题写着“随机”“前瞻性”或“回顾性”就定性。当前任务中已确认的事实会复用，不反复盘问。

设计确认后，再检索 [EQUATOR 指南库](https://www.equator-network.org/reporting-guidelines/)，进入指南制定方或原始发表页面，核实并读取当前适用的清单及扩展版。设计未明确时，只做不依赖具体设计的工作或暂定指南探索，不宣布某类指南已经核查通过。无需每次额外指定 EQUATOR。工具支持时下载官方文件；只能在线阅读时，会明确说明没有保存本地文件。

结果增加 **Guideline Manifest（指南记录）**，交代选择理由、版本、链接、核实日期、实际读取范围和限制；另提供 **Reporting Guideline Matrix（逐项核查表）**，列出条目、稿件位置、报告状态、具体改法和待作者补充的信息。期刊指定旧清单时会说明与当前指南的差异；叙述性综述不会被机械套用系统综述标准。清单完整不等于研究质量合格或低偏倚风险。

自动获取需要运行平台提供联网及相应文件能力。Skill 本身不内置全部指南，也不新增下载程序依赖。禁止联网或官方文件无法读取时，会据已有材料给出有限评价，不会声称已核查最新版。单纯纠正错别字不重复检索。同一任务的多审稿人使用同一份冻结、未批注的指南包，前轮问题由编辑单独保管。

```text
请帮我写作或审核这篇稿件。先识别研究类型，从 EQUATOR 获取当前适用
报告指南及扩展，说明版本和来源，再逐项给出改进建议。保留事实，
缺失信息标为待作者补充。
```

### 投稿或修回前的最后一遍检查

说“投稿前最后一遍检查”即可触发十项核查，输出具体位置、最小修改建议及检查状态表。尽量提供当前稿件、图表、补充材料、参考文献、期刊要求，以及修回时的决定信和回复文件。整稿修改或多审稿人工作流结束时，也会执行这些检查。

这是一套跨专科通用核查。缺少材料会标为“无法核验”，不会默认通过；不会擅自统一冲突数字、把极差改标为四分位距、按作者排名推断贡献，或自动重写整篇稿件。引用格式按期刊要求，术语偏好按当前任务处理。

```text
请对当前版本及附件做投稿前最后一遍检查：核对重复数字、引用、图表编号、
流程人数、注册信息、缩写、统计表达、入排标准和实际作者贡献。
如为修回稿，逐条核对审稿问题及子问题、回复和实际修改是否对应。
给出问题位置、最小改法、待作者确认事项及检查状态表；保留原文件，
不要代替我更改数据。
```

### 期刊指导与 AI 使用披露

从 0.7.1 起，增加[离线统计审查路由](skills/evidence-first-medical-writing/references/statistical-policy-router.md)及精简的 JAMA／NEJM 参考。即使期刊网站无法访问，也能继续有范围限制的方法学审查；明确区分统计方法问题和目标期刊要求，包括因果措辞、多重性及结果显示规则的差异。本地参考标注来源范围与时效限制，不代表已核查最新版。需要判断现行合规性时仍核实目标期刊要求，EQUATOR 流程不变，不打包第三方指南原文。

从 0.7.0 起，现有指南记录进一步区分“设计定义、报告规范、目标期刊要求、可选方法学参考、AI 使用政策”。研究类型有歧义时参考 JAMA 定义；临床原创研究的方法与统计写作／审查可参考 NEJM 相应章节，但不覆盖实际研究事实、作者设计确认或其他期刊的格式要求。无法联网或仅有未标日期的副本时明确说明限制，不把第三方原文打包发布。

投稿或再次投稿前，简短提醒作者按实际目标期刊的现行政策如实披露 AI 使用。**不维护 AI 使用记录，不收集使用历史问卷，不默认生成披露草稿**；披露由作者负责。换期刊、文章类型或当前任务变化时，重新核对受影响的政策，而不是追踪历史使用。

当前请求与已核实的期刊政策冲突时，会明确提醒并暂停受影响的操作；政策不明则说明尚未核实，不能靠披露绕过禁止用途。基础拼写检查的豁免不能自动扩展到实质改写。检测分数或水印结果不能证明 AI 使用比例、期刊合规，也不能免除应有的如实披露。

```text
投稿前，请简短提醒我按目标期刊现行政策披露 AI 使用，提示当前请求与
政策的冲突。若换期刊或任务变化，请重新核对政策。不要记录我的 AI 使用
历史，不要给我历史使用问卷，也不要自动起草披露声明。
```

### 可选：原始／分析数据与统计核查

以下可选核查与 AI 披露提醒相互独立，不以提供原始数据为写作前提。

你可以提供有权共享、已经去标识化的原始或分析数据、变量字典，以及相关统计输出或代码，供 skill 在限定范围内只读核对图表。这不是必需步骤；拒绝或无法提供数据，仍可写作和审稿。不要上传可识别的患者记录或未经许可的数据；去标识化本身不等于允许上传到任何平台。

核查会记录实际计算了什么、分析人群及舍入规则、差异发生在哪里，以及哪些仍无法确认。不同组出现相同数值或重复记录，可作为查阅原始记录的线索，但可能有合理原因，不能直接认定造假。统计意见会区分文字澄清与需作者批准的重新分析；不擅自删数据、追求显著性、向外传输数据或出具真实性证明。

“与原始数据一致”和“论文内部逻辑自洽”分别给出结果。即使复算通过，仍检查正文、图表之间的人群、分母、时间点、单位、方向与结论是否矛盾；没有原始数据，也会进行这层内部检查。

需要深入复算或图像／数据专门核查时，会说明所需能力，并在核实可用性后建议统计专家或相应 skill；不会未经同意安装工具或传输数据。

### 独立多审稿人工作流

当你希望临床、方法学、统计、证据或编辑视角分别独立审稿，再由单独的编辑代理裁决并监督修改时，可使用这一工作流。默认运行两轮，按文章类型选择 3–4 名审稿人，另设 1 名编辑，并完成期刊规范、引用完整性、修改回归和最终文件检查。所有报告都会明确标为模拟同行评审。

如需真正独立的并行评估，应在可用时选择 multi-agent 或 Ultra-capable mode；若不可用，skill 会采用彼此隔离的顺序审稿，并明确说明独立性只是近似实现。

```bash
python3 -B -m unittest discover -s tests -v
```

```bash
python3 -B scripts/validate_release.py --require-release
```

第一条命令测试随包脚本与打包规则；第二条核对发布元数据、链接、受保护文件与校验和，追加 `--archive /path/to/release.zip` 可逐项比对发布包。两者都不验证实际写作表现；行为测试需在新的对话中运行相应的[虚拟案例](evals/README.md)，按实际输出评分。
