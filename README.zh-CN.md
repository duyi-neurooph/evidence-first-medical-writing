# 循证医学科研写作

**Evidence-First Medical Writing**

<img src="assets/logo.png" alt="循证医学科研写作图标" width="144">

[English README](README.md)

这是一个由 Yi 发布和维护的双语 Codex skill，用于以研究可信度和证据边界为先，规划、诊断、修改和检查医学科研论文。

方法来源说明：本工作流基于多来源医学科研写作与编辑实践，提炼可迁移的方法原则、工作流与检查表。公开仓库不指向任何具体第三方来源或贡献者。

仓库地址：<https://github.com/duyi-neurooph/evidence-first-medical-writing>

## 主要能力

- 建立研究任务卡、PICO-T、核心命题和 IMRaD 大纲；
- 检查研究问题、设计、终点、分析、结果与结论是否一致；
- 在语言润色前发现研究诚信和报告风险；
- 应用特定报告指南前，与作者确认真实研究类型，针对缺失的关键事实提问，不直接相信“随机”“前瞻性”等标签；
- 在实质性写作或审稿前，从 EQUATOR 及官方来源获取适用报告指南，记录版本并逐项提出改进建议；
- 修改题目、摘要、正文各章节、图表、投稿信和审稿回复；
- 运行“独立多审稿人—编辑裁决—迭代修改”的模拟同行评审，并维护 Decision Ledger 和 Non-Regression Check；
- 对最终投稿文件进行十项交叉核查，覆盖数据、引用、编号、流程、注册、术语、统计表达、入排标准、作者贡献和修回回复；
- 可选核对获准共享、去标识化的数据与图表及统计方法，提供异常线索与核查建议，不声称能够判定造假；
- 支持随机研究、观察性研究、诊断、预测、系统综述/Meta、病例类和短文等常见类型；
- 按 `P0 可信度阻断项`、`P1 研究逻辑`、`P2 结构与自明性`、`P3 语言与格式` 分级输出问题。

## 安全边界

本 skill 不得：

- 编造数据、方法、注册、伦理批准、引文或审稿决定；
- 为追求显著性而改变终点、阈值、分析集或结论；
- 把相关性升级为因果，或把无统计学显著性写成等效；
- 隐瞒阴性主要结果、局限、偏离、错误或不确定性；
- 冒充真实个人或复现可识别的个人文风；
- 在没有可核验许可时宣称授权、背书、隶属或官方身份；
- 暴露患者信息、保密手稿、私人通信或身份映射。

它用于辅助写作和研究推理，不能替代临床判断、统计签字、伦理审查、法律意见或目标期刊的最新要求。

### 使用时自动获取适用报告指南

实质性规划、写作、改写或审稿时，skill 会先与你讨论研究类型：说明初步判断及依据，必要时只追问关键事实，例如治疗由谁决定、是否真正随机分配、如何选入受试者，以及研究计划和结局收集的时间关系。不能仅凭标题写着“随机”“前瞻性”或“回顾性”就定性。当前任务中已确认的事实会复用，不反复盘问。

设计确认后，再检索 [EQUATOR 指南库](https://www.equator-network.org/reporting-guidelines/)，进入指南制定方或原始发表页面，核实并读取当前适用的清单及扩展版。设计未明确时，只做不依赖具体设计的工作或暂定指南探索，不宣布某类指南已经核查通过。无需每次额外指定 EQUATOR。工具支持时下载官方文件；只能在线阅读时，会明确说明没有保存本地文件。

结果增加 **Guideline Manifest（指南记录）**，交代选择理由、版本、链接、核实日期、实际读取范围和限制；另提供 **Reporting Guideline Matrix（逐项核查表）**，列出条目、稿件位置、报告状态、具体改法和待作者补充的信息。期刊指定旧清单时会说明与当前指南的差异；叙述性综述不会被机械套用系统综述标准。清单完整不等于研究质量合格或低偏倚风险。

自动获取需要运行平台提供联网及相应文件能力。Skill 本身不内置全部指南，也不新增下载程序依赖。禁止联网或官方文件无法读取时，会据已有材料给出有限评价，不会声称已核查最新版。单纯纠正错别字不重复检索。同一任务的多审稿人使用同一份冻结、未批注的指南包，前轮问题由编辑单独保管。

```text
请帮我写作或审核这篇稿件。先识别研究类型，从 EQUATOR 获取当前适用
报告指南及扩展，说明版本和来源，再逐项给出改进建议。保留事实，
缺失信息标为待作者补充。
```

### 投稿或修回前的最后一遍检查

说“投稿前最后一遍检查”即可触发十项核查，输出具体位置、最小修改建议及检查状态表。尽量提供当前稿件、图表、补充材料、参考文献、期刊要求，以及修回时的决定信和回复文件。整稿修改或多审稿人工作流结束时，也会执行这些检查。

这是一套跨专科通用核查。缺少材料会标为“无法核验”，不会默认通过；不会擅自统一冲突数字、把极差改标为四分位距、按作者排名推断贡献，或自动重写整篇稿件。引用格式按期刊要求，术语偏好按当前任务处理。

```text
请对当前版本及附件做投稿前最后一遍检查：核对重复数字、引用、图表编号、
流程人数、注册信息、缩写、统计表达、入排标准和实际作者贡献。
如为修回稿，逐条核对审稿问题及子问题、回复和实际修改是否对应。
给出问题位置、最小改法、待作者确认事项及检查状态表；保留原文件，
不要代替我更改数据。
```

### 可选：原始／分析数据与统计核查

你可以提供有权共享、已经去标识化的原始或分析数据、变量字典，以及相关统计输出或代码，供 skill 在限定范围内只读核对图表。这不是必需步骤；拒绝或无法提供数据，仍可写作和审稿。不要上传可识别的患者记录或未经许可的数据；去标识化本身不等于允许上传到任何平台。

核查会记录实际计算了什么、分析人群及舍入规则、差异发生在哪里，以及哪些仍无法确认。不同组出现相同数值或重复记录，可作为查阅原始记录的线索，但可能有合理原因，不能直接认定造假。统计意见会区分文字澄清与需作者批准的重新分析；不擅自删数据、追求显著性、向外传输数据或出具真实性证明。

“与原始数据一致”和“论文内部逻辑自洽”分别给出结果。即使复算通过，仍检查正文、图表之间的人群、分母、时间点、单位、方向与结论是否矛盾；没有原始数据，也会进行这层内部检查。

需要深入复算或图像／数据专门核查时，会说明所需能力，并在核实可用性后建议统计专家或相应 skill；不会未经同意安装工具或传输数据。

### 独立多审稿人工作流

当你希望临床、方法学、统计、证据或编辑视角分别独立审稿，再由单独的编辑代理裁决并监督修改时，可使用这一工作流。默认运行两轮，按文章类型选择 3–4 名审稿人，另设 1 名编辑，并完成期刊规范、引用完整性、修改回归和最终文件检查。所有报告都会明确标为模拟同行评审。

如需真正独立的并行评估，应在可用时选择 multi-agent 或 Ultra-capable mode；若不可用，skill 会采用彼此隔离的顺序审稿，并明确说明独立性只是近似实现。

可复制模板：

```text
请对所附临床医学稿件进行独立多审稿人模拟同行评审和迭代修改。
所有报告和编辑决定均须明确标为 simulated peer review（模拟同行评审）。

目标期刊：
文章类型：
稿件版本：
期刊指南：
是否允许检索公开报告指南：是
审稿人角色：
审稿轮数：2
是否允许更广泛的文献检索：
受保护的作者决定或未公开数据：
已确认的研究类型和事实依据（如已知）：
是否需要可选的去标识化数据核查：是／否／暂无法提供
所需交付物：

每名审稿人必须独立评估同一个冻结版本，不得看到其他审稿人的意见。
单独的编辑代理应综合报告，必要时拒绝薄弱或冲突的建议，监督修改，并对
新的冻结稿启动全新的第二轮审稿。维护 Decision Ledger，避免已纠正的问题
被重新引入。审核 claim-citation 匹配、引文位置、自明性、统计解释、表格、
图示、期刊规范以及 AI 化或口号化表达。未经作者明确同意，不得改变数据或
科学含义。
```

请勿在公开 GitHub issue 中粘贴保密手稿、可识别健康信息、未发表数据或私人审稿通信。
