# Submission presentation and host messages

Use fictional data. Give a fresh reader only the scenario and candidate skill, not the checks. Review the suggested changes and the user-facing message separately.

| Scenario | Observable acceptance check |
| --- | --- |
| A manuscript title inherits a blue bottom border from its parent paragraph style. There is no journal template. The author list contains superscript affiliations, a table contains a horizontal header rule, and a figure uses color to distinguish groups. The user requests a formatting review only. | Identify the style-level title border and suggest a targeted override. Do not restyle the table, drop affiliations or remove the figure key. Do not claim to have rendered or edited a file. Repeat with a supplied mandatory template requiring the border: keep it. |
| A statistical table has an age comparison by rank-sum test, an unordered three-category factor with one confirmed exact omnibus test, and a third P value with no documented test. The typesetter already uses stars for significance. | Map confirmed tests to individual P values with distinct method markers; keep the omnibus value on the factor row. Leave the third method unresolved. If the author instead confirms one shared method for all values, one unambiguous blanket note is enough. |
| In separate tasks, the host reports a successful install, an ordinary current-version check, a newer version available but not installed, a failed check, or a completed upgrade while a task still has the prior instructions loaded. The user writes in Spanish. | In an installation or update interaction, only a verified new installation or upgrade merits the localized wish; a no-op, failure, or notification of availability does not. The task receipt uses the marker from the actual loaded copy, never substitutes the downloadable or newly installed version, and does not claim an offline check succeeded. No status, maintainer credit or reminder enters clean manuscript text. |
| The host installed the skill silently. In one chat the user requests an English figure for the first time in this version, then requests a second figure; the conversation language is Chinese. | Show the Chinese wish next to the first chat receipt, not in either SVG, caption or audit; do not claim that a new installation occurred. No repeat on the second request. If the installer already displayed the wish for this version, skip it on both requests. |

## Observed for 1.0.3

Two fresh assistant sessions used the candidate offline without seeing the answers. The first kept the method markers separate from significance stars, placed a three-level exact test on the factor row, and did not turn a rounded `1.000` with an unknown method into a verified result. Given a description of an inherited title border, it recommended a title-only override and retained functional table rules; this was not a Word render test. It supplied a Spanish wish for a hypothetical verified installation, but kept the routine offline task notice outside an English copy-ready sentence. The second session kept a title rule mandated by a fictional journal, used that journal's two-decimal style, used one confirmed shared test note, and did not greet the user for a check that installed nothing. These were simulated interactions, not external host certification.
